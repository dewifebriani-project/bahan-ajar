Profil Insiden Siber Bank Digital Syariah & Taksonomi Serangan

Anda bertindak sebagai Lead Cybersecurity & IT Forensic Auditor pada Bank Digital Syariah Nusantara. Anda diminta menganalisis 25 log rekaman insiden keamanan siber yang terekam pada server SIEM (Security Information and Event Management) selama periode Juni–Agustus 2026.

Ringkasan Insiden: Terdapat 25 insiden keamanan siber mulai dari serangan phishing spear, ransomware cabang, eksploitasi SQL injection portal nasabah, percobaan pembobolan credential stuffing, hingga manipulasi pembulatan saldo (salami technique).

Investigasi Forensik Kasus 1: Serangan Ransomware LockBit (INC-2026-004)
⏱ 15 menit

Analisis Cyber Kill Chain (tahapan serangan dari pengintaian hingga enkripsi data) pada insiden infeksi ransomware di server KCP Bogor:

Tahapan Cyber Kill Chain Temuan Forensik pada Insiden INC-2026-004 Kelemahan Kontrol yang Dieksploitasi
1. Reconnaissance (Pengintaian) Hacker melakukan port scanning massal dan menemukan Port RDP 3389 terbuka ke publik. Ketiadaan firewall rule restriksi IP publik pada router cabang.
2. Weaponization & Delivery Brute-force credential admin RDP berhasil dibobol dalam 40 menit karena password lemah. Ketiadaan Multi-Factor Authentication (MFA) dan account lockout threshold.
3. Exploitation & Execution Hacker menonaktifkan service antivirus lokal dan mengeksekusi payload LockBit.exe. Akun admin RDP memiliki hak superuser lokal tanpa pemisahan privilege.
4. Actions on Objectives (Enkripsi) 12.000 file dokumen nasabah dienkripsi dengan ekstensi .lockbit dan meninggalkan pesan tebusan. Folder sharing jaringan tidak terisolasi dari subnet workstation staf.
QUERY SQL FORENSIK INSIDEN DENGAN STATUS COMPROMISED
-- Kueri SQL mencari seluruh insiden dengan status Compromised dan estimasi kerugian finansial > 0: SELECT Incident_ID, Timestamp, Threat_Category, Attack_Vector, Target_Asset, Severity_Level, Financial_Impact_Estimate_Rp, Forensic_Finding_Summary FROM Cybersecurity_Incidents_Log WHERE Incident_Status = 'Compromised' OR Financial_Impact_Estimate_Rp > 0 ORDER BY Financial_Impact_Estimate_Rp DESC;

Desain Arsitektur Pertahanan Berlapis (Defense-in-Depth Framework)
⏱ 15 menit

Rancang arsitektur keamanan berlapis ganda (Defense-in-Depth) untuk melindungi Sistem Informasi Akuntansi Bank Digital Syariah dari perimeter luar hingga inti data:

Lapisan Pertahanan Fokus Proteksi Aset Spesifikasi Teknologi Kontrol SIA yang Wajib Diterapkan
1. Perimeter Layer Gerbang Lalu Lintas Internet Next-Generation Firewall (NGFW), Anti-DDoS Scrubbing Center, Web Application Firewall (WAF).
2. Network Layer Segmentasi Jaringan Internal VLAN Segmentation (Isolasi server core banking dari LAN kantor cabang), VPN dengan otentikasi sertifikat SSL.
3. Endpoint Layer Perangkat Kerja Karyawan EDR (Endpoint Detection & Response), proteksi port USB storage, automated OS patch management.
4. Application Layer Aplikasi Software SIA Input Validation & Sanitization, Secure Coding Lifecycle (DevSecOps), Multi-Factor Authentication (MFA).
5. Data Layer Database & Backup Enkripsi Database (AES-256), Immutable WORM Backup Snapshot, Data Loss Prevention (DLP).
6. Human Layer Kesadaran Pegawai (Human Firewall) Simulasi phishing bulanan, pelatihan verifikasi Tabayyun email, larangan peminjaman password.

Protokol Tanggap Insiden Syariah: SOP CSIRT & Prinsip Tabayyun
⏱ 10 menit

Ketika terjadi insiden keamanan siber, Tim Tanggap Insiden Keamanan Komputer (Computer Security Incident Response Team / CSIRT) harus bertindak berdasarkan standar NIST SP 800-61 yang diselaraskan dengan etika syariah:

Fase Respons Insiden Aktivitas Operasional CSIRT Integrasi Dimensi Nilai Syariah
1. Preparation (Kesiapsiagaan) Penyusunan playbook insiden, simulasi kebocoran data, dan pengujian disaster recovery berkala. Prinsip Ihtiyath: Kewaspadaan proaktif sebelum bencana terjadi.
2. Detection & Analysis Verifikasi log SIEM, isolasi IP mencurigakan, dan analisis forensik digital. Prinsip Tabayyun (QS. Al-Hujurat: 6): Meneliti kebenaran bukti tanpa berasumsi gegabah.
3. Containment & Eradication Pemutusan host terinfeksi dari jaringan LAN, penghapusan malware, dan pencabutan kredensial bocor. Saddu adz-Dzari'ah: Menutup pintu penyebaran mafsadat secara cepat.
4. Post-Incident Recovery & Lessons Pemulihan data dari snapshot backup, pelaporan wajib ke OJK/BSSN dalam 1x24 jam, dan evaluasi. Prinsip Muhasabah & As-Sidq: Transparansi pelaporan insiden kepada regulator dan nasabah.

3 Tantangan Analisis Mandiri & Format Laporan PDF
⏱ 10 menit

🎯 3 Tantangan Analisis Mandiri (Wajib Dimuat dalam Laporan Akhir)

Tantangan 1 — Kuantifikasi Kerugian & Efektivitas Kontrol: Dari 25 insiden pada dataset, hitung: 1) Total kerugian finansial yang berhasil dicegah (Financial Loss Avoided), 2) Total kerugian yang terealisasi (Actual Realized Loss), dan 3) Evaluasi tingkat keberhasilan sistem deteksi (WAF, EDR, SIEM).
Tantangan 2 — Blueprint Arsitektur Zero Trust: Rancang diagram alur prinsip Zero Trust Architecture (Never Trust, Always Verify) pada akses database akuntansi perbankan syariah dari luar kantor.
Tantangan 3 — Tanggung Jawab Hukum & Syariah Kebocoran Data (UU PDP): Berdasarkan UU Perlindungan Data Pribadi (UU No. 27/2022) dan Fatwa MUI, jelaskan sanksi hukum bagi pengelola data yang lalai dan kewajiban ganti rugi terhadap nasabah yang dirugikan (Dhaman).
