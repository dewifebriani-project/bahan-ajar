Tujuan Pembelajaran & Trust Services Framework

Capaian CPMK-3 (Bloom C4 Menganalisis) · 5 Prinsip Keandalan Sistem Akuntansi
✓

Pengendalian berbasis teknologi informasi merupakan tulang punggung keandalan Sistem Informasi Akuntansi modern. AICPA dan CPA Canada merumuskan Trust Services Framework yang menetapkan 5 kriteria utama sistem informasi yang dapat dipercaya:

PILAR 1
Security (Keamanan)
Perlindungan fisik dan logis terhadap akses tidak sah ke aset data akuntansi.
PILAR 2
Confidentiality
Perlindungan informasi sensitif bisnis organisasi dari kebocoran ke pihak ketiga.
PILAR 3
Privacy (Privasi)
Pengelolaan dan pengamanan data pribadi nasabah/karyawan (PII) sesuai regulasi UU PDP.
PILAR 4
Processing Integrity
Pemrosesan transaksi secara akurat, lengkap, tepat waktu, dan dengan otorisasi sah.
PILAR 5
Availability
Ketersediaan sistem dan data saat dibutuhkan untuk operasional dan pengambilan keputusan.

Target Capaian Pembelajaran (CPMK-3)

  • Membedah IT General Controls (ITGC): Menganalisis tata kelola akses, change management, operasional batch, dan disaster recovery plan (DRP).
  • Menguasai 9 Teknik Input Controls: Mengimplementasikan validasi form transaksi (Field, Sign, Limit, Range, Size, Completeness, Validity, Reasonableness, Check Digit).
  • Mengevaluasi Processing & Output Controls: Memeriksa batch controls (Financial total, Hash total, Record count), cross-footing, dan teknik data masking.
  • Mengadopsi Tata Kelola COBIT 2019: Memetakan pemisahan tugas dalam departemen TI (SoD IT) pada 5 domain COBIT.
  • Mengintegrasikan Nilai Syariah Khilafah & Syahadah Digital: Memaknai log jejak audit sebagai saksi digital yang tidak dapat disangkal di hadapan Allah SWT (QS. Al-Zalzalah: 7–8, QS. Yasin: 65).

02

IT General Controls (ITGC) & Tata Kelola COBIT 2019

Pengendalian Lingkungan TI · Pemisahan Tugas (SoD IT) · 5 Domain Tata Kelola COBIT
✓

IT General Controls (ITGC) adalah pengendalian menyeluruh yang berlaku pada seluruh sistem komputer dan infrastruktur organisasi. Jika ITGC lemah, maka kontrol aplikasi di dalamnya tidak dapat dipercaya.

4 Domain Utama IT General Controls (ITGC)

Domain 1
Access Controls
Manajemen hak akses pengguna (RBAC), otentikasi ganda (MFA), password complexity, dan penonaktifan akun pegawai nonaktif (deprovisioning).
Domain 2
Change Management
Prosedur formal pengajuan perubahan kode, pengujian di lingkungan UAT/Staging, dan pemisahan tegas dari server Production.
Domain 3
Computer Operations
Penjadwalan otomatis job harian (batch processing), pemantauan kapasitas server, antivirus, dan penanganan insiden sistem.
Domain 4
Business Continuity (DRP)
Pencadangan data berkala (Daily Backup Snapshot), replikasi data ke offsite cloud, dan pengujian berkala pemulihan bencana.

Pemisahan Tugas Wajib dalam Organisasi TI (IT Segregation of Duties)

Peran Personel TI Tanggung Jawab Utama Larangan Keras (Aktivitas yang Tidak Boleh Dirangkap)
Systems Analysts & Programmers Merancang dan menulis kode software aplikasi SIA. Dilarang memiliki hak akses langsung ke server dan database Production yang sedang beroperasi.
Computer Operators Menjalankan dan memantau eksekusi batch job di server production. Dilarang mengubah atau memodifikasi source code program aplikasi.
Database Administrator (DBA) Mengelola struktur tabel, performa, dan integritas database. Dilarang menginput transaksi keuangan atau merangkap sebagai programmer aplikasi bisnis.
Security Officer / CISO Memantau log keamanan, ancaman siber, dan menegakkan kebijakan akses. Independen dari tim operasional TI dan melapor langsung ke Komite Audit / Direksi.
Kerangka Kerja COBIT 2019: ISACA menerbitkan COBIT 2019 yang membagi tata kelola TI menjadi 5 Domain: EDM (Evaluate, Direct, Monitor) untuk tingkat Dewan/Direksi, serta 4 domain manajemen: APO (Align, Plan, Organize), BAI (Build, Acquire, Implement), DSS (Deliver, Service, Support), dan MEA (Monitor, Evaluate, Assess).

03

IT Application Controls: 9 Teknik Validasi Input Data

Garbage In, Garbage Out Prevention · Pengujian Data Form Transaksi SIA Terprogram
✓

Prinsip Garbage In, Garbage Out (GIGO) menegaskan bahwa secanggih apa pun software akuntansi, jika data mentah yang dimasukkan salah, maka output laporan keuangan akan menyesatkan. Input Controls dirancang untuk menyaring dan menolak data salah sebelum disimpan ke database.

9 Teknik Validasi Input Data Terprogram

Teknik Input Control Mekanisme Pengujian Sistem Contoh Kasus Transaksi Perbankan Syariah
1. Field Check (Type Check) Memastikan data yang diinput hanya berisi karakter dengan tipe data yang tepat (numerik, teks, tanggal). Menolak input nominal setoran 1500000A karena terdapat karakter huruf pada field angka.
2. Sign Check Memastikan angka bernilai tanda aritmatika yang sesuai (positif atau negatif). Menolak input penarikan tabungan bertanda minus -500.000.
3. Limit Check Menguji apakah nilai input berada di bawah atau di atas batas batas mutlak yang telah ditetapkan. Memblokir pencairan pembiayaan Rp 65 Juta jika wewenang Account Officer maksimal Rp 50 Juta.
4. Range Check Menguji apakah nilai input berada di dalam rentang batas minimum dan maksimum yang diperbolehkan. Menolak usia debitur 12 tahun (kebijakan 17–75 tahun) atau nisbah bagi hasil 110%.
5. Size Check Memastikan jumlah karakter input sesuai dengan panjang field yang disyaratkan. Menolak Nomor Induk Kependudukan (NIK) yang hanya terdiri dari 14 digit (wajib 16 digit).
6. Completeness Check Memeriksa bahwa seluruh kolom data yang bersifat wajib (mandatory/required) tidak boleh kosong (NULL). Memblokir penyimpanan akad murabahah jika nama nasabah atau nomor akad belum diisi.
7. Validity Check Mencocokkan kode input terhadap daftar referensi master file yang sah. Menolak kode akun GL-99999 jika tidak terdaftar dalam Master Chart of Accounts (COA).
8. Reasonableness Check Menguji kewajaran logis hubungan antara dua atau lebih elemen data yang saling terkait. Menolak potongan pelunasan dini pembiayaan sebesar 95% dari pokok pembiayaan.
9. Check Digit Verification Memvalidasi keaslian nomor identitas menggunakan algoritma matematis (Luhn Modulo 10 checksum). Mendeteksi salah ketik digit pada nomor kartu ATM atau nomor rekening nasabah.

04

Processing & Output Controls dalam Sistem Informasi Akuntansi

Integritas Pemrosesan Data · Batch Controls (Financial & Hash Total) · Pengamanan Output
✓

Setelah data lolos validasi input, sistem harus menjamin bahwa pemrosesan transaksi dan penyajian laporan keuangan bebas dari kesalahan kalkulasi, data hilang, maupun kebocoran informasi.

1. Pengendalian Batch Processing (Batch Controls)

Ketika ribuan transaksi diproses secara berkala dalam satu kelompok (batch), sistem menghitung 3 angka kontrol pengendali:

Financial Total
Total Moneter (Rupiah)
Jumlah total nilai uang dari seluruh transaksi dalam batch (Contoh: Total setoran angsuran Rp 145.000.000).
Hash Total
Total Kontrol Non-Moneter
Jumlah penjumlahan dari field numerik yang tidak bermakna finansial, seperti menjumlahkan nomor rekening atau NIK untuk mendeteksi baris yang hilang.
Record Count
Jumlah Baris Transaksi
Jumlah total baris catatan transaksi dalam batch (Contoh: Tepat 150 transaksi diproses tanpa ada yang tertinggal).

2. Processing Controls Lainnya

  • Cross-Footing Balance Test: Memverifikasi kesamaan saldo debet dan kredit dalam jurnal, serta memeriksa keselarasan antara total baris dan total kolom pada neraca lajur.
  • Zero-Balance Test: Memastikan bahwa akun perantara/kliring (clearing accounts) bersaldo nol setelah pemrosesan batch selesai (Contoh: Akun Kas Antar Cabang harus nol setelah rekonsiliasi).
  • Data Matching: Pencocokan otomatis 3 dokumen (Three-Way Matching) antara Purchase Order, Receiving Report, dan Vendor Invoice sebelum pembayaran disetujui.

3. Output Controls (Pengendalian Keluaran)

  • Data Masking / Redaction: Menyembunyikan digit sensitif nomor kartu atau NIK nasabah pada slip bukti dan laporan (Contoh: 4512-****-****-8821) untuk menjaga privasi.
  • Laporan Rekonsiliasi Otomatis: Pencocokan berkala antara saldo buku pembantu piutang murabahah dengan akun kontrol di buku besar (GL).
  • Watermarking & Enkripsi PDF: Penyematan identitas pengunduh dan enkripsi AES-256 pada laporan keuangan dan log audit yang diekspor.

Jejak Audit Kekal (Audit Trail) & Konsep Syahadah Digital

Mandat Khilafah dalam Tata Kelola TI · Log Transaksi sebagai Saksi Digital Tak Terbantahkan
✓

Dalam perspektif Islam, manusia mengemban amanah sebagai Khalifah di muka bumi, termasuk dalam merancang dan mengoperasikan sistem teknologi akuntansi. Jejak audit elektronik (audit trail) bukan sekadar instrumen audit kepatuhan, melainkan wujud Syahadah Digital (kesaksian elektronik) yang merekam setiap rekam jejak amal manusia.

فَمَن يَعْمَلْ مِثْقَالَ ذَرَّةٍ خَيْرًا يَرَهُ ۝ وَمَن يَعْمَلْ مِثْقَالَ ذَرَّةٍ شَرًّا يَرَهُ
"Maka barangsiapa mengerjakan kebaikan seberat zarrah, niscaya dia akan melihat (balasan)nya, dan barangsiapa mengerjakan kejahatan seberat zarrah, niscaya dia akan melihat (balasan)nya."
QS. Al-Zalzalah [99]: 7–8 — Prinsip Kepastian Pencatatan Amalan: Tidak Ada Transaksi yang Luput dari Jejak Audit Ilahiah
الْيَوْمَ نَخْتِمُ عَلَىٰ أَفْوَاهِهِمْ وَتُكَلِّمُنَا أَيْدِيهِمْ وَتَشْهَدُ أَرْجُلُهُم بِمَا كَانُوا يَكْسِبُونَ
"Pada hari ini Kami tutup mulut mereka; tangan mereka akan berkata kepada Kami dan kaki mereka akan memberi kesaksian terhadap apa yang dahulu mereka kerjakan."
QS. Yasin [36]: 65 — Konsep Syahadah Digital: Log Sistem sebagai Saksi Otomatis yang Mengungkap Kebenaran Tanpa Dapat Disangkal (Non-Repudiation)

Dimensi Syariah dalam Arsitektur Kontrol TI

1. Al-Khilafah & Amanah IT
Kewenangan mengelola database dan infrastruktur server adalah mandat amanah. Mengabaikan kontrol atau mematikan log audit adalah bentuk khianat.
Prinsip Tata Kelola TI Islami
2. As-Syahadah & Non-Repudiation
Log jejak audit kekal memastikan pelaku transaksi tidak dapat menyangkal perbuatannya (non-repudiation), menegakkan keadilan pembuktian forensik.
Prinsip Integritas Bukti Hukum
3. Al-Adl dalam Alokasi Wewenang
Pemisahan tugas (SoD) antara analis, programmer, dan operator mencegah penumpukan kekuasaan sepihak yang memicu tirani dan kecurangan.
Prinsip Keadilan Sistemik
4. Hifz al-Mal & Zero Error (Itqan)
Pengendalian validasi input dan batch controls adalah wujud kesungguhan (itqan) untuk menjaga harta umat dari salah saji dan ketidaktepatan bagi hasil.
Prinsip Ketelitian Akuntansi Syariah

Studi Kasus Audit IT: Pengujian Kontrol Aplikasi Core Banking

Evaluasi Temuan Log Audit · Anomali Batch Hash Total & Pelanggaran Change Management
✓

Tim Auditor Sistem Informasi melakukan pengujian substantif atas data log kontrol aplikasi core banking pada BPRS Amanah Ummah yang tercatat dalam dataset-it-controls-audit-p07.csv. Ditemukan dua insiden defisiensi kritis:

KASUS 1: ANOMALI BATCH HASH TOTAL MISMATCH (LOG-2026-013)
  • Gejala Sistem: Pada proses closing harian BATCH-0701-B, sistem mendeteksi ketidaksesuaian Hash Total: nilai pada header batch tercatat 592.810, namun kalkulasi aktual sistem hanya 582.810 (selisih tepat 10.000).
  • Penyebab Forensik: Satu transaksi angsuran murabahah terputus di tengah transmisi jaringan akibat timeout server dan belum tersimpan sempurna di database buku pembantu.
  • Tindakan Pengendalian: Modul Processing Control berhasil menahan (suspend) batch agar tidak ter-posting ke General Ledger sampai data rekonsiliasi diperbaiki.
KASUS 2: PELANGGARAN FATAL CHANGE MANAGEMENT OLEH DBA (LOG-2026-015)
  • Peristiwa: Database Administrator (DBA) mengeksekusi perintah langsung ALTER TABLE customer pada server production tanpa tiket persetujuan (Change Request Ticket).
  • Pelanggaran ITGC: Melanggar prinsip Change Management COBIT 2019 (Domain BAI06). Segala perubahan struktur tabel wajib melalui pengujian lingkungan UAT dan persetujuan Change Advisory Board (CAB).
  • Deteksi: Jejak audit database (Database Activity Monitoring) secara otomatis mencatat User ID, IP, dan script yang dijalankan sebagai temuan Material Weakness ITGC.
Persiapan Sesi Praktikum: Pada lembar Praktikum-07-AIS.html, Anda akan menguji secara langsung 25 data log kontrol aplikasi, merekonstruksi penghitungan Hash Total, serta merancang matriks ITGC dan SoD IT berbasis standar COBIT 2019!
